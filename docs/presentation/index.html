THE PROPOSAL

A new build tool shouldn’t require a new build platform.

01:15–02:10 · One boundary, two owners. “The developer owns an image and a source-controlled command. Konflux owns checkout, fixed Tasks, credentials, output packaging, and provenance. The developer does not author a Task or choose a ServiceAccount. Click the command to show the actual argv contract. Builds may fetch dependencies: isolation and hermeticity are separate. Production also needs admission controls for influences the release predicate does not show.”

Discuss ADR 73 ↗
PROPOSAL ≠ PRODUCTION GUARANTEE
Working proof of concept

Build outputs → OCI → signed provenance → integration policy → release unpacking.

Still platform responsibilities

Immutable Task identities, admission enforcement, isolation, and Source VSA verification.

Implementation differences
  • Repo: build-cmd + build-args. ADR: script-path.
  • Local Tasks use namespace names and a development CLI image.
  • Repo policy permits resource overrides; the ADR rejects taskRunSpecs more broadly.
  • Current policy recognizes the catalog builder image and output type.
  • Source identity checks do not prove Source L4 review or a Source VSA.
  • Unpack validates the payload; Conforma is the preceding signature and policy gate.

06:15–07:00 · Close on value and the remaining work. “The value is faster build-tool adoption and a shared trust model. This repo proves the flow, not the full production assurance claim. Production needs approved immutable Tasks, admission controls, correct isolation and Chains configuration, plus separate Source VSA evidence. The proposed direction is more developer freedom inside one platform-owned boundary.”
